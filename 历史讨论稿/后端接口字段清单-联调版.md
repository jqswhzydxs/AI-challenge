# 后端接口字段清单 - 联调版

> 生成依据：当前后端 Controller、DTO、VO 代码。  
> 更新时间：2026-07-25  
> Base URL：`http://localhost:8080`  
> 业务接口前缀：`/api`

## 1. 联调总规则

### 1.1 统一响应结构

除报表 CSV 导出接口外，后端统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

分页接口的 `data` 结构：

```json
{
  "total": 0,
  "pageNum": 1,
  "pageSize": 10,
  "records": []
}
```

### 1.2 鉴权请求头

除 `POST /api/auth/login` 和接口文档资源外，其他 `/api/**` 接口都需要：

```http
Authorization: Bearer <登录接口返回的 token>
```

注意：`Bearer` 后面必须有一个空格。只传原始 token 会返回 `401`。

### 1.3 角色权限

| 接口路径 | 允许角色 |
|---|---|
| `/api/system/**` | `SYSTEM_ADMIN` |
| `/api/production/**` | `SYSTEM_ADMIN`, `PRODUCTION_DISPATCHER` |
| `/api/energy/**` | `SYSTEM_ADMIN`, `ENERGY_MANAGER` |
| 其他 `/api/**` | 任意已登录用户 |

### 1.4 通用查询参数 `PageQueryDTO`

多个列表、趋势和历史接口会复用这些 Query 参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pageNum` | number | 否 | 页码，默认 `1` |
| `pageSize` | number | 否 | 每页条数，默认 `10` |
| `date` | string | 否 | 日期，格式 `yyyy-MM-dd` |
| `status` | string | 否 | 状态筛选 |
| `startTime` | string | 否 | 开始时间，可传 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss` |
| `endTime` | string | 否 | 结束时间，可传 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss` |
| `startDate` | string | 否 | 开始日期，格式 `yyyy-MM-dd` |
| `endDate` | string | 否 | 结束日期，格式 `yyyy-MM-dd` |
| `interval` | number | 否 | 聚合粒度，单位分钟；`>=1440` 时部分接口按日聚合 |

### 1.5 时间格式

| Java 类型 | JSON 示例 |
|---|---|
| `LocalDate` | `"2026-07-17"` |
| `LocalDateTime` | `"2026-07-17 16:10:30"` |
| 字符串时间 | 以接口返回为准，例如 `"00:01:00"` 或 `"2026-07-17 00:00"` |

### 1.6 ID 字段格式

后端雪花 ID 是 `Long`，超过 JavaScript 安全整数范围。接口返回时所有 `Long/long` 字段统一按字符串输出：

```json
{
  "scheduleId": "2081219222897274881",
  "taskId": "2081219222897274881"
}
```

`BigDecimal` 指标字段仍按普通 JSON 数字输出：

```json
{
  "elecCoefficient": 14.0000,
  "deadlineCompliance": 100.00
}
```

## 2. 认证接口

### 2.1 用户登录

`POST /api/auth/login`

权限：公开接口。

请求体 `LoginDTO`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 密码 |

示例：

```json
{
  "username": "admin",
  "password": "123456"
}
```

响应 `LoginVO`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `token` | string | JWT token |
| `userId` | number | 用户 ID |
| `username` | string | 用户名 |
| `role` | string | 主角色 |
| `roles` | string[] | 角色列表 |

### 2.2 当前用户信息

`GET /api/auth/userinfo`

权限：已登录。

请求头：`Authorization: Bearer <token>`

响应：同 `LoginVO`。

### 2.3 退出登录

`POST /api/auth/logout`

权限：已登录。

响应：`data = null`。JWT 是无状态退出，前端清理本地 token 即可。

|---|---|---|---|
| `scheduleDate` | string | 是 | 排产日期，`yyyy-MM-dd` |
| `planHorizon` | number | 是 | 计划跨度，通常 `24` |
| `planUnit` | string | 否 | 计划单位，通常 `hour` |
| `dataGranularity` | string | 否 | 模型底层数据粒度 |
| `objective` | string | 否 | 优化目标，如 `MIN_EC`、`MIN_COST` |
| `constraints` | object | 否 | 约束条件 |

示例：

```json
{
  "scheduleDate": "2026-07-17",
  "planHorizon": 24,
  "planUnit": "hour",
  "dataGranularity": "1 minute",
  "objective": "MIN_EC",
  "constraints": {
    "elecCoefficient": 13.278524
  }
}
```

响应：`TaskVO`。

### 4.3 查询排产方案详情

`GET /api/production/schedules/{scheduleId}`

权限：`SYSTEM_ADMIN`、`PRODUCTION_DISPATCHER`

路径参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scheduleId` | string | 是 | 排产方案 ID，后端 Long 按字符串传 |

响应：`SchedulePlanVO`，详情接口包含 `details`。

前端请求示例：

```ts
// 注意：后端 ID 是 19 位 Long，前端不要先转成 number，否则会丢精度。
const scheduleId = '2081219222897275000'

const res = await request.get(`/api/production/schedules/${scheduleId}`, {
  headers: {
    Authorization: `Bearer ${token}`
  }
})
```

如果前端通过 Vite 代理访问后端，可以请求：

```http
GET http://localhost:5175/api/production/schedules/2081219222897275000
Authorization: Bearer <token>
```

如果没有配置 Vite 代理，则直接请求后端：

```http
GET http://localhost:8080/api/production/schedules/2081219222897275000
Authorization: Bearer <token>
```

## 12. 前端最容易接错的点

1. 所有真实业务接口都要加 `Authorization: Bearer <token>`。
2. 排产历史接口用 `page/size`，其他大部分分页用 `pageNum/pageSize`。
3. 生产模块需要 `SYSTEM_ADMIN` 或 `PRODUCTION_DISPATCHER`，能源模块需要 `SYSTEM_ADMIN` 或 `ENERGY_MANAGER`。
4. `GET /api/reports/export/{type}` 返回 CSV 文件流，不是 JSON。
5. `GET /api/energy/plan/{planDate}` 需要先调用 `POST /api/energy/plan/generate` 生成过方案，否则可能返回 `404`。
6. `POST /api/optimize/joint/generate` 需要已有 `scheduleId` 和 `energyPlanId`，不能直接空跑。
7. 字段命名全部按后端 Java VO 的 camelCase 返回，例如 `energyPlanId`、`costReductionRate`、`carbonEmissionTco2`。
8. 后端 ID 多数是 19 位 Long，接口返回已经统一转成字符串；前端也应按字符串保存和拼接路径，不要转成 JavaScript `number`。
