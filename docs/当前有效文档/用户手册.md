# 用户手册

> 系统名称：生产-能源交互式优化平台  
> 版本：v1.2  
> 整理日期：2026-08-08

## 1. 系统概述

本系统用于工业园区轧钢生产与能源供给协同优化。当前版本将能源数据接入方式调整为“模拟采集装置/外部采集程序按分钟推送到后端”，前端正式操作时不再要求用户上传能源 CSV。调度人员只需录入次日计划日期和订单产量，系统会从数据库中读取已采集的能源时序数据，生成小时级生产排产方案和能源调控方案。

当前系统规划的是：

```text
排产日订单需求在 24 小时内如何分配生产，
以及能源设备如何配合该生产计划运行。
```

当前系统已接入订单需求，但仍不是完整订单级 APS 排产系统。系统会按订单数量、交期和优先级形成小时级需求，不会直接生成每笔订单的独立工序路线。若页面出现 2026-07-17 数据，通常是数据库 seed 中的演示数据；前端录入新的计划日期和订单产量后，会生成新的算法任务和新的排产方案。

## 2. 环境配置

### 2.1 基础环境

| 环境 | 要求 |

| JDK | 17 |

### 2.2 后端环境变量

在 PowerShell 中可设置：

```powershell
$env:DB_USERNAME="root"
```

```powershell
$env:MAX_UPLOAD_FILE_SIZE="100MB"
$env:MAX_UPLOAD_REQUEST_SIZE="100MB"
```

## 6. 生产排产功能

### 6.1 查看订单列表

进入生产排产模块后，可查看订单列表。订单数据会作为排产算法的需求输入。

当前算法实际使用的生产需求输入是：

```text
订单 plannedQuantity + dueTime + priority
```

### 6.2 上传订单 CSV

系统支持上传订单 CSV，写入 `production_order` 表。订单编号 `orderNo` 已存在时更新，不存在时新增。

接口：

```text
POST /api/production/orders/import
```

CSV 示例：

```csv
orderNo,productName,productSpec,plannedQuantity,unit,dueTime,priority,status,remark
PO-20260803-001,热轧卷板,Q235B / 3.0mm,2.8,t,2026-08-03 12:00:00,1,PENDING,上传订单
PO-20260803-002,热轧卷板,Q355B / 4.5mm,3.2,t,2026-08-03 18:00:00,2,PENDING,上传订单
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `orderNo` | 是 | 订单编号 |
| `productName` | 是 | 产品名称 |
| `plannedQuantity` | 是 | 计划数量 |
| `dueTime` | 是 | 交付时间 |
| `productSpec` | 否 | 产品规格 |
| `unit` | 否 | 单位，默认 `t` |
| `priority` | 否 | 优先级，默认 `1` |
| `status` | 否 | 状态，默认 `PENDING` |
| `remark` | 否 | 备注 |

注意：订单上传后会写入 `production_order` 表。生成方案时，后端会按排产日导出未完成订单给 Python 算法；方案成功后，参与排产的订单状态会更新为 `SCHEDULED`。当前系统仍不是完整订单级 APS，不生成每笔订单的独立工序路线。

### 6.3 录入次日订单产量并生成方案

推荐前端页面文案：

```text
录入次日计划日期和订单产量，系统将使用已采集能源数据生成生产-能源协同优化方案。
```

用户需要提供：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 计划日期 | `2026-08-08` | 必填，表示生成哪一天的日级排产方案 |
| 订单产量 | `1200` | 必填，单位默认为吨 |
| 产品名称 | `热轧卷板` | 可选，不填时系统使用“次日轧钢计划” |

正式接口：

```http
POST /api/production/schedules/generate-from-collected-data
Content-Type: application/json
```

请求示例：

```json
{
  "scheduleDate": "2026-08-08",
  "plannedQuantity": 1200,
  "productName": "热轧卷板"
}
```

后端处理逻辑：

1. 自动写入或更新一条 `AUTO-计划日期` 生产订单。
2. 从 `energy_realtime_data` 读取最近 7 天能源时序数据。
3. 导出算法所需的 `input.csv` 和 `orders.csv`。
4. 调用 Python 算法生成 `output.json`。
5. 解析并写入排产方案、MPC 实时调控结果和评价指标。

### 6.4 能源 CSV 补录/联调入口

旧接口仍然保留，但只建议作为历史数据补录、算法联调或兜底测试使用，不再作为前端正式页面主入口。

```http
POST /api/production/schedules/generate-from-raw-data
Content-Type: multipart/form-data
```

CSV 字段要求：

| 字段 | 说明 |
| --- | --- |
| `timestamp` / `date` / `datetime` | 时间列 |
| `elec` / `Usage_kWh` / `power` / `power_kw` | 用电量或功率列 |
| `steam` | 可选，蒸汽字段 |

推荐联调文件：

```text
D:\桌面\挑战杯\AI-challenge\data\algorithm\steel_data_cleaned.csv
```

系统算法最终按 1 分钟粒度计算。若输入 15 分钟粒度数据，系统会自动截取最近 7 天并插值为 1 分钟粒度。

### 6.5 生成方案操作步骤

1. 进入“生产排产”页面。
2. 选择或填写次日计划日期。
3. 填写次日订单产量。
4. 点击“生成优化方案”。
5. 系统返回 `taskId`。
6. 前端轮询任务状态。
7. 任务成功后，根据 `resultId` 查询排产方案详情。

接口流程：

```text
POST /api/production/schedules/generate-from-collected-data
GET  /api/tasks/{taskId}
GET  /api/production/schedules/{resultId}
```

### 6.6 查看排产结果

生成成功后，系统会展示：

- 排产方案名称。
- 计划日期。
- 订单总需求吨数。
- 总生产量。
- 总能耗。
- 优化前 EC。
- 优化后 EC。
- EC 降低率。
- 最优加热温度。
- 最优轧制速度。
- 24 小时生产明细。

排产明细通常包含：

| 字段 | 说明 |
| --- | --- |
| 小时序号 | 0-23 |
| 开始时间 | 当前小时开始 |
| 结束时间 | 当前小时结束 |
| 小时需求 | 当前小时需求量 |
| 小时排产量 | 当前小时生产量 |

### 6.7 查看排产历史

## 7. 能源运行功能

### 7.1 实时能源监控

能源监控页面展示：

- 用电量。
- 蒸汽消耗。
- 碳排放。
- 功率因数。
- 能源成本估算。

当前版本在没有真实现场接口时，由后端内置模拟采集装置每分钟自动生成一条能源数据并写入 `energy_realtime_data`。前端能源页面继续调用：

```http
GET /api/energy/realtime
```

页面建议按分钟刷新，展示最新用电、蒸汽、碳排、功率因数和负荷类型。

### 7.2 能源运行方案

能源运行方案用于展示生产计划对应的能源消耗、成本、蒸汽和碳排放。生成逻辑为：

1. 若指定日期有能源时序数据，系统按小时聚合。
2. 若没有对应日期能源数据，系统根据排产明细派生能源方案。
3. 系统结合峰谷电价和蒸汽单价估算能源成本。

峰谷时段：

| 类型 | 时间 |
| --- | --- |
| 谷段 | `00:00-08:00,22:00-24:00` |
| 峰段 | `08:00-22:00` |

### 7.3 设备状态

设备状态页面展示锅炉、汽机、外购电接口等设备运行情况。当前主要约束为：

| 设备 | 运行范围 |
| --- | --- |
| 锅炉 | `20-80 MW` |
| 汽机 | `5-30 MW` |

## 8. MPC 实时调控

MPC 页面用于展示实时能源调控指令。方案生成时，算法输出的 `realtime_control` 会作为初始指令入库；系统启动后，滚动 MPC 定时任务会每分钟读取最新能源采集点、当前小时排产计划和上一轮调控指令，计算实际负荷与计划负荷的偏差，并写入新的锅炉、汽机、外购电修正指令。

### 8.1 最新调控指令

可查看：

- 锅炉负荷。
- 汽机出力。
- 外购电。
- 功率因数目标。
- 未来 5 分钟用电预测。
- 未来 5 分钟蒸汽预测。

### 8.2 历史调控记录

MPC 历史页面可按日期或分页查看历史调控指令。若 `REALTIME_MPC_ENABLED=true`，该表会随每分钟采集数据持续刷新，而不是只在生成方案时写入一次。

导入或生成的数据会写入：

```text
mpc_realtime_control
```

联调时也可以手动触发一次滚动 MPC：

```http
POST /api/realtime-control/tick
```

## 9. 协同评估

协同评估用于判断生产排产方案和能源运行方案是否匹配。

它回答的问题是：

```text
排产方案回答“生产怎么排”；
能源方案回答“能源怎么跟上”；
协同评估回答“两者匹配得好不好”。
```

核心指标：

| 指标 | 说明 |
| --- | --- |
| MAPE | 平均绝对百分误差 |
| 仿真精度 | `100% - MAPE` |
| EC 降低率 | 优化后单位产量能耗降低比例 |
| ER 可执行率 | 方案满足约束的比例 |

当前示例口径：

| 指标 | 数值 |
| --- | --- |
| MAPE | `3.55%` |
| 仿真精度 | `96.45%` |
| EC 降低率 | `5.15%` |
| ER | `100%` |

## 11. 常见问题

### 11.1 前端是否还需要上传能源 CSV？

正式流程不需要。能源数据由后端内置模拟采集装置或外部采集程序按分钟写入 `energy_realtime_data`。前端只需录入次日计划日期和订单产量。能源 CSV 上传接口只作为补录、联调或兜底测试入口。

### 11.2 上传的 CSV 是排产数据吗？

不是。能源 CSV 是历史能源数据，包含时间、用电、蒸汽等信息；订单编号、订单重量、交期和优先级来自订单 CSV，并写入 `production_order` 表。

### 11.3 系统是不是订单级排产？

当前是订单驱动的小时级排产，但还不是完整订单级 APS。系统会把排产日订单按交期累加成 24 小时需求，规划每小时生产多少；暂不生成每笔订单的独立工序路线。

### 11.4 为什么现在只填写订单产量？

因为当前演示流程把前端录入的次日订单产量自动转换为一条生产订单，后端再导出为算法输入。算法优化的是该订单需求在 24 小时内的生产分配和能源调控。

### 11.5 如果还显示 2026-07-17 是怎么回事？

2026-07-17 是数据库 seed 演示数据。录入次日计划日期和订单产量生成方案后，应使用任务返回的 `taskId` 查询任务，任务成功后使用 `resultId` 查询新方案。

### 11.6 算法失败怎么办？

可先检查：

- `energy_realtime_data` 是否已有最近 7 天能源数据。
- 模拟采集装置是否启用。
- 数据是否连续且满足 1 分钟或 15 分钟粒度。
- 后端是否能访问 Python。
- `target/algorithm-tasks/{taskId}/algorithm.log` 是否存在异常。

## 2026-08-10 使用口径更新

当前正式演示流程中，前端仍只需要录入次日计划日期和订单产量，不需要上传能源 CSV。后端内置采集装置默认从算法历史样本 `data/algorithm/steel_data_cleaned.csv` 回放能源数据并按分钟入库，真实接入时可关闭 `MOCK_DEVICE_ENABLED`，改由外部采集程序推送。点击生成后，后端调用算法一次性输出生产排产 `daily_plan`、能源运行 `energy_plan` 和 MPC 初始调控 `realtime_control`；页面展示的能源方案优先来自算法 `energy_plan`，只有算法结果缺失该块时才使用后端规则派生兜底。
