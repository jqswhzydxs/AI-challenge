# 用户手册

> 系统名称：生产-能源交互式优化平台  
> 版本：v1.1  
> 整理日期：2026-08-03

## 1. 系统概述

本系统用于工业园区轧钢生产与能源供给协同优化。用户上传历史能源数据 CSV，并填写计划日期、当天总需求吨数和最晚完成时间后，系统会调用算法生成小时级生产排产方案和能源调控方案。

当前系统规划的是：

```text
日总产量 D_total 在 24 小时内如何分配生产，
以及能源设备如何配合该生产计划运行。
```

当前系统不是订单级 APS 排产系统，不会区分订单编号、单订单重量、交货窗口和订单优先级。若页面出现 2026-07-17 数据，通常是数据库 seed 中的演示数据；用户上传 CSV 后会生成新的算法任务和新的排产方案。

## 2. 环境配置

### 2.1 基础环境

| 环境 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 或 Windows Server 2022 |
| JDK | 17 |
| Maven | 3.9+ |
| MySQL | 8.x |
| Python | 3.10+ |

Python 算法默认使用标准库，不需要额外安装第三方包。

### 2.2 后端环境变量

在 PowerShell 中可设置：

```powershell
$env:DB_USERNAME="root"
$env:DB_PASSWORD="你的MySQL密码"
$env:ALGORITHM_RUNTIME="python"
$env:ALGORITHM_COMMAND="python"
$env:ALGORITHM_SCRIPT="generate_plan.py"
$env:ALGORITHM_WORKING_DIR="D:\桌面\挑战杯\AI-challenge\data\algorithm"
$env:ALGORITHM_TASK_DIR="D:\桌面\挑战杯\AI-challenge\target\algorithm-tasks"
$env:ALGORITHM_TIMEOUT_SECONDS="180"
```

默认上传文件限制为 50MB。如需调整：

```powershell
$env:MAX_UPLOAD_FILE_SIZE="100MB"
$env:MAX_UPLOAD_REQUEST_SIZE="100MB"
```

### 2.3 启动后端

```powershell
cd D:\桌面\挑战杯\AI-challenge
mvn -pl AI-web -am spring-boot:run
```

启动成功后访问：


## 6. 生产排产功能

### 6.1 查看订单列表

进入生产排产模块后，可查看订单列表。当前订单数据主要用于页面展示和业务说明，暂未作为算法排产输入。

当前算法实际使用的生产需求输入是：

```text
D_total = 当天总需求吨数
```

### 6.2 上传订单 CSV

系统支持上传订单 CSV，写入 `production_order` 表。订单编号 `orderNo` 已存在时更新，不存在时新增。

接口：

```text
POST /api/production/orders/import
```

CSV 示例：

```csv
orderNo,productName,productSpec,plannedQuantity,unit,dueTime,priority,status,remark
PO-20260803-001,热轧卷板,Q235B / 3.0mm,2.8,t,2026-08-03 12:00:00,1,PENDING,上传订单
PO-20260803-002,热轧卷板,Q355B / 4.5mm,3.2,t,2026-08-03 18:00:00,2,PENDING,上传订单
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `orderNo` | 是 | 订单编号 |
| `productName` | 是 | 产品名称 |
| `plannedQuantity` | 是 | 计划数量 |
| `dueTime` | 是 | 交付时间 |
| `productSpec` | 否 | 产品规格 |
| `unit` | 否 | 单位，默认 `t` |
| `priority` | 否 | 优先级，默认 `1` |
| `status` | 否 | 状态，默认 `PENDING` |
| `remark` | 否 | 备注 |

注意：当前订单上传用于订单展示和需求管理，暂未接入订单级 APS 排产。当前算法仍以当天总需求 `D_total` 生成小时级排产方案。

### 6.3 上传历史能源数据并生成方案

推荐前端页面文案：

```text
上传历史能源数据，并填写当日生产需求，系统将生成生产-能源协同优化方案。
```

用户需要提供：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 历史能源 CSV | `steel_data_cleaned.csv` | 至少包含时间和用电字段 |
| 计划日期 | `2026-08-03` | 生成方案所属日期 |
| 总需求吨数 | `9.5` | 当天需要完成的总产量 |
| 最晚完成时间 | `2026-08-03 23:00:00` | 当天生产任务完成时间 |

CSV 字段要求：

| 字段 | 说明 |
| --- | --- |
| `timestamp` / `date` / `datetime` | 时间列 |
| `elec` / `Usage_kWh` / `power` / `power_kw` | 用电量或功率列 |
| `steam` | 可选，蒸汽字段 |

推荐测试文件：

```text
D:\桌面\挑战杯\AI-challenge\data\algorithm\steel_data_cleaned.csv
```

如需测试 1 分钟数据，可使用：

```text
D:\桌面\挑战杯\AI-challenge\data\algorithm\steel_data_1min_fixed.csv
```

### 6.4 生成方案操作步骤

1. 进入“生产排产”页面。
2. 点击“上传历史能源数据”。
3. 选择 CSV 文件。
4. 填写计划日期、总需求吨数、最晚完成时间。
5. 点击“生成优化方案”。
6. 系统返回 `taskId`。
7. 前端轮询任务状态。
8. 任务成功后，根据 `resultId` 查询排产方案详情。

接口流程：

```text
POST /api/production/schedules/generate-from-raw-data
GET  /api/tasks/{taskId}
GET  /api/production/schedules/{resultId}
```

### 6.5 查看排产结果

生成成功后，系统会展示：

- 排产方案名称。

- 总需求吨数。

- 最优加热温度。
- 最优轧制速度。

排产明细通常包含：

| 字段 | 说明 |

## 7. 能源运行功能

### 7.1 实时能源监控

能源监控页面展示：

- 用电量。
- 蒸汽消耗。
- 碳排放。
- 功率因数。
- 能源成本估算。

### 7.2 能源运行方案

能源运行方案用于展示生产计划对应的能源消耗、成本、蒸汽和碳排放。生成逻辑为：

1. 若指定日期有能源时序数据，系统按小时聚合。
2. 若没有对应日期能源数据，系统根据排产明细派生能源方案。
3. 系统结合峰谷电价和蒸汽单价估算能源成本。

峰谷时段：

| 类型 | 时间 |
| --- | --- |
| 谷段 | `00:00-08:00,22:00-24:00` |
| 峰段 | `08:00-22:00` |

### 7.3 设备状态

设备状态页面展示锅炉、汽机、外购电接口等设备运行情况。当前主要约束为：

| 设备 | 运行范围 |
| --- | --- |
| 锅炉 | `20-80 MW` |
| 汽机 | `5-30 MW` |

## 9. 协同评估

协同评估用于判断生产排产方案和能源运行方案是否匹配。

它回答的问题是：

```text
排产方案回答“生产怎么排”；
能源方案回答“能源怎么跟上”；
协同评估回答“两者匹配得好不好”。
```

核心指标：

| 指标 | 说明 |
| --- | --- |
| MAPE | 平均绝对百分误差 |
| 仿真精度 | `100% - MAPE` |
| EC 降低率 | 优化后单位产量能耗降低比例 |
| ER 可执行率 | 方案满足约束的比例 |

当前示例口径：

| 指标 | 数值 |
| --- | --- |
| MAPE | `3.55%` |
| 仿真精度 | `96.45%` |
| EC 降低率 | `5.15%` |
| ER | `100%` |

## 11. 常见问题

### 11.1 上传的 CSV 是排产数据吗？

不是。CSV 是历史能源数据，包含时间、用电、蒸汽等信息，不包含订单编号、订单重量、交货窗口和订单优先级。

### 11.2 系统是不是订单级排产？

当前不是。当前系统是日总量级排产，即给定当天总需求 `D_total`，系统规划 24 小时内每小时生产多少。

### 11.3 为什么需要填写总需求吨数？

因为当前 MILP 模型把当天总产量视为外部固定输入。算法优化的是小时分配和能源调控，不负责决定“今天总共生产多少”。

### 11.4 如果还显示 2026-07-17 是怎么回事？

2026-07-17 是数据库 seed 演示数据。上传 CSV 后应使用任务返回的 `taskId` 查询任务，任务成功后使用 `resultId` 查询新方案。

### 11.5 算法失败怎么办？

可先检查：

- 文件是否为 CSV。
- 文件是否超过上传限制。
- 是否包含时间列和用电列。
- 数据是否连续且至少一周以上。
- 后端是否能访问 Python。
- `target/algorithm-tasks/{taskId}/algorithm.log` 是否存在异常。
