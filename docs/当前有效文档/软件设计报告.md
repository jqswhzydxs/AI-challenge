# 软件设计报告

> 项目名称：生产-能源交互式优化平台  
> 版本：v1.0 正式整理稿  
> 整理日期：2026-08-01

## 1. 项目概述

本系统面向钢铁生产与能源运行协同分析场景，围绕生产排产、能源运行、MPC 实时调控和协同评估构建后端服务。系统支持用户上传钢铁能源原始 CSV 数据，由后端创建算法任务并默认调用 Python 工程化算法程序生成日级排产方案和 MPC 调控结果，再完成结果入库、方案展示、能源测算、约束校验和效果分析。

当前系统定位为：

> 基于用户上传原始能源数据和算法组工程化算法模型的生产计划自动生成、能源运行测算、MPC 调控展示和协同评估系统。

其中，“协同评估”用于判断生产计划与能源运行方案匹配情况，不表述为已经完成独立协同优化求解模型。

## 2. 设计目标

- 支撑用户登录、角色识别和基础权限控制。
- 支撑上传原始能源 CSV 数据并异步调用 Python 算法生成排产方案，MATLAB 版本作为旧版兜底。
- 保留算法排产结果 `daily_plan_v3.2.json` 导入与展示，作为联调和兜底入口。
- 支撑能源历史数据、能源运行方案和能源分析指标展示。
- 支撑算法生成的 MPC 实时调控指令入库、查询和历史展示。
- 支撑生产计划与能源运行方案的协同评估、约束校验和指标分析。
- 支撑首页看板、报表统计、告警和系统管理页面。
- 保留算法原始结果和任务记录，便于追踪、复现和答辩说明。

| `POST /api/production/schedules/import-daily-plan` | 导入算法组日级排产 JSON |
| `GET /api/production/schedules/{scheduleId}` | 排产方案详情 |

当前主排产案例来自算法组 `daily_plan_v3.2.json`，核心指标为：

### 4.4 能源运行模块

能源运行模块负责实时能源数据、能源运行方案、设备状态、负荷预测、能源趋势、能源分析和碳减排展示。

主要接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/energy/realtime` | 实时能源数据 |
| `POST /api/energy/plan/generate` | 生成能源运行方案 |
| `GET /api/energy/plan/{planDate}` | 查询能源方案 |
| `GET /api/energy/plans/history` | 能源方案历史 |
| `GET /api/energy/device-status` | 能源设备状态 |
| `GET /api/energy/load-forecast` | 负荷预测 |
| `GET /api/energy/consumption-trend` | 能耗趋势 |
| `GET /api/energy/analysis` | 能源分析摘要 |
| `GET /api/energy/trend` | 能源统计趋势 |
| `GET /api/energy/carbon-reduction` | 碳减排趋势 |

能源方案生成逻辑：

```text
优先查询指定日期 energy_realtime_data
        -> 有数据：按小时聚合电耗、蒸汽、碳排
        -> 无数据：读取排产方案明细，按电耗预测派生
        -> 结合峰谷电价和蒸汽单价计算能源成本
```

峰谷时段口径：

| 类型 | 时段 |
| --- | --- |
| 谷段 | `00:00-08:00,22:00-24:00` |
| 峰段 | `08:00-22:00` |
| 平段 | 算法报告未设单独平段，系统保留兼容字段 |

### 4.5 MPC 实时调控模块

MPC 模块负责展示算法组实时调控指令，包括锅炉负荷、汽机出力、外购电、功率因数目标和未来 5 分钟预测。

主要接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/realtime-control/latest` | 最新 MPC 调控指令 |
| `GET /api/realtime-control/history` | MPC 历史记录 |
| `POST /api/realtime-control/import` | 导入实时调控 JSON |

约束校验：

| 指令 | 范围 |
| --- | --- |
| 锅炉负荷 | `20-80 MW` |
| 汽机出力 | `5-30 MW` |
| 功率因数目标 | `0.95` |

后端在导入实时调控数据时校验锅炉和汽机范围，避免前端或外部接口导入越界模拟数据。

## 5. 关键流程设计

### 5.1 原始数据上传生成流程

```text
前端上传原始 CSV
        -> 后端保存文件并创建 algorithm_task
        -> 后端调用 Python generate_plan.py
        -> 算法输出 output.json
        -> 后端解析 daily_plan
        -> 写入 production_schedule_plan
        -> 拆分 24 条 production_schedule_detail
        -> 写入 evaluation_metric
        -> 后端解析 realtime_control
        -> 写入 mpc_realtime_control
        -> 自动触发能源运行方案生成
        -> 自动触发协同评估生成
```

任务状态通过 `GET /api/tasks/{taskId}` 查询。`SUCCESS` 时，`resultId` 对应生成的排产方案 ID。

### 5.1.1 算法排产导入流程（兜底）

```text
前端上传 / 粘贴 daily_plan_v3.2.json
        -> 后端校验 timestamp、plan_horizon、schedule
        -> 写入 algorithm_task
        -> 写入 production_schedule_plan
        -> 拆分 24 条 production_schedule_detail
        -> 写入 evaluation_metric
        -> 自动触发能源运行方案生成
        -> 自动触发协同评估生成
```

### 5.2 能源运行方案生成流程

```text
接收 planDate
        -> 查询当天能源时序数据
        -> 有数据则按小时聚合
        -> 无数据则按排产明细派生
        -> 计算电力成本、蒸汽成本、总能源成本
        -> 写入 energy_plan / energy_plan_detail
```

### 5.3 协同评估流程

```text
读取排产方案和能源方案
        -> 对齐小时级时序
        -> 计算成本、能耗、MAPE、EC、ER
        -> 校验锅炉负荷 20-80MW
        -> 写入冲突记录
        -> 返回协同评估结果
```

### 5.4 MPC 导入流程

```text
接收实时调控 JSON
        -> 解析 timestamp / control / forecast
        -> 校验锅炉负荷 20-80MW
        -> 校验汽机出力 5-30MW
        -> 写入 algorithm_task
        -> 写入或更新 mpc_realtime_control
```

## 6. 安全与异常设计

- 使用 JWT 进行登录态认证。
- 统一返回结构：`code/message/data`。
- 通过 `GlobalExceptionHandler` 处理业务异常、参数异常和系统异常。
- 使用逻辑删除字段 `deleted` 管理业务主表。
- 操作日志通过切面记录接口访问。

### 6.1 统一返回结构

后端所有接口统一返回以下 JSON 结构，便于前端统一处理成功、失败、提示和跳转逻辑。

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `int` | 业务响应码，`200` 表示成功，非 `200` 表示失败 |
| `message` | `string` | 响应提示，可直接用于页面提示 |
| `data` | `object/null` | 成功时返回业务数据，失败时通常为 `null` |

### 6.2 常见异常返回

参数错误：

```json
{
  "code": 400,
  "message": "参数错误，请检查请求字段",
  "data": null
}
```

未登录或 Token 无效：

```json
{
  "code": 401,
  "message": "请先登录",
  "data": null
}
```

无权限访问：

```json
{
  "code": 403,
  "message": "无权限访问该资源",
  "data": null
}
```

业务数据不存在：

```json
{
  "code": 404,
  "message": "数据不存在",
  "data": null
}
```

业务规则校验失败：

```json
{
  "code": 400,
  "message": "锅炉负荷必须在 20-80 MW 范围内",
  "data": null
}
```

系统异常：

```json
{
  "code": 500,
  "message": "系统异常，请稍后重试",
  "data": null
}
```

### 6.3 前端处理建议

- `code = 200`：正常读取 `data` 渲染页面。
- `code = 401`：清除本地登录态并跳转登录页。
- `code = 403`：提示无权限，不跳转或跳转无权限页面。
- `code = 404`：展示空状态或“暂无数据”。
- `code = 400`：展示 `message`，提示用户检查输入。
- `code = 500`：展示系统异常提示，并保留重试入口。
