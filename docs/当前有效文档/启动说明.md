# 启动说明

> 适用项目：生产-能源交互式优化平台后端 `AI-challenge`
> 当前后端端口：`8080`

## 1. 环境要求

- JDK 17
- Maven 3.9+
- MySQL 8.x
- 数据库字符集建议：`utf8mb4`

源码、SQL、Markdown 文档均按 UTF-8 保存。若 PowerShell 中直接 `Get-Content` 看到中文乱码，可先执行：

```powershell
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

## 2. 创建数据库

```sql
CREATE DATABASE IF NOT EXISTS challenge_cup_energy
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;
```

## 3. 配置环境变量

PowerShell 示例：

```powershell
$env:DB_URL="jdbc:mysql://localhost:3306/challenge_cup_energy?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai"
$env:DB_USERNAME="root"
$env:DB_PASSWORD="你的数据库密码"
$env:JWT_SECRET="请替换为至少32位的随机字符串"
$env:JWT_EXPIRE_SECONDS="86400"
$env:ALGORITHM_TRAINING_DAYS="7"
$env:MOCK_DEVICE_ENABLED="true"
$env:MOCK_DEVICE_BACKFILL_DAYS="7"
$env:REALTIME_MPC_ENABLED="true"
```

也可以不设置 `DB_URL`，默认连接本机 `challenge_cup_energy` 数据库。

## 4. 建表和导入数据

在 MySQL 客户端中进入项目目录后执行：

```sql
SOURCE database/sql/数据库建表SQL.sql;
SOURCE reset_all.sql;
SOURCE database/sql/seed_demo_data.sql;
SOURCE database/sql/seed_steel_data.sql;
SOURCE database/sql/seed_steel_1min.sql;
SOURCE database/sql/seed_mpc_control.sql;
SOURCE database/sql/seed_mpc_hourly.sql;
```

说明：

- `数据库建表SQL.sql`：创建业务表。
- `reset_all.sql`：清空业务数据，保留表结构。
- `seed_demo_data.sql`：用户、角色、产线、设备、订单、报表等演示基础数据。
- `seed_steel_data.sql`：15 分钟粒度钢铁能耗数据。
- `seed_steel_1min.sql`：1 分钟粒度钢铁能耗数据，文件较大，导入耗时会更长。
- `seed_mpc_control.sql` / `seed_mpc_hourly.sql`：MPC 实时调控结果。

如果只做快速接口冒烟，可先导入 `seed_demo_data.sql`、`seed_mpc_control.sql`、`seed_mpc_hourly.sql`。当前版本后端默认启用模拟采集装置，启动时会自动向 `energy_realtime_data` 补齐最近 7 天分钟级模拟数据，因此正式演示流程不再要求前端上传能源 CSV。

## 5. 编译打包

```powershell
mvn -DskipTests package
```

成功后主应用包位于：

```text
AI-web/target/AI-web-1.0-SNAPSHOT.jar
```

## 6. 启动后端

方式一：Maven 启动。

```powershell
mvn -pl AI-web spring-boot:run
```

方式二：Jar 启动。

```powershell
java -jar AI-web/target/AI-web-1.0-SNAPSHOT.jar
```

启动成功后：

- 后端 Base URL：`http://localhost:8080/api`
- Swagger UI：`http://localhost:8080/swagger-ui.html`
- OpenAPI JSON：`http://localhost:8080/v3/api-docs`

## 7. 前端联调

前端 `.env` 建议：

```env
VITE_USE_MOCK=false
VITE_API_BASE_URL=http://localhost:8080/api
```

如前端通过 Vite 代理访问后端，保持 Base URL 为 `/api`，并把代理目标改到 `http://localhost:8080`。

当前前端正式排产流程只需要提供计划日期和订单产量：

```http
POST /api/production/schedules/generate-from-collected-data
Content-Type: application/json
```

```json
{
  "scheduleDate": "2026-08-08",
  "plannedQuantity": 1200
}
```

旧接口 `POST /api/production/schedules/generate-from-raw-data` 仅作为历史能源 CSV 补录和联调兜底入口。

## 9. 当前数据口径说明

- 方案生成时的 MPC 初始指令来自算法输出或其 SQL seed。
- 当前没有真实现场接口时，后端内置模拟采集装置每分钟写入 `energy_realtime_data`；真实接入时可关闭模拟装置，改由外部采集程序调用 `/api/energy/realtime/push`。
- `REALTIME_MPC_ENABLED=true` 时，后端每分钟读取最新能源采集点、当前小时排产计划和上一轮控制指令，向 `mpc_realtime_control` 写入滚动修正结果。
- 日级排产正式流程由前端录入计划日期和订单产量触发，后端读取最近 7 天已采集能源数据调用算法。
- 能源方案由后端基于实时能源数据或排产方案派生生成。
- 协同优化由后端基于排产方案和能源方案派生评价。
- 趋势、分析、报表接口主要从 `energy_realtime_data`、`energy_plan_detail`、`report_statistic`、`evaluation_metric` 聚合。
## 2026-08-10 启动配置补充

内置采集装置默认启用历史样本回放：

```powershell
$env:MOCK_DEVICE_MODE="replay"
$env:MOCK_DEVICE_REPLAY_FILE="data/algorithm/steel_data_cleaned.csv"
```

启动后 `MockEnergyDeviceTask` 会按分钟把样本数据重写为当前时间并写入 `energy_realtime_data`，用于替代默认正弦模拟。若样本文件不可用，系统才会使用正弦兜底并标记 `data_quality=SYNTHETIC_FALLBACK`。日规划任务完成后，后端会优先导入算法输出中的 `energy_plan` 作为能源方案，旧 Java 派生逻辑仅在算法输出缺失能源方案时使用。
